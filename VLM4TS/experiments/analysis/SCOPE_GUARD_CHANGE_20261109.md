# 인접 후보 화면과 집계의 범위 보호

## 확인한 문제

한 Stage1 후보를 확인하는 224틱 화면 안에 다른 후보가 함께 나타날 수 있음. 확대 범위뿐 아니라 전체 그래프와 heatmap에서도 다른 후보가 보이므로, VLM의 event 판정이 실제로 어느 후보에 대한 것인지 기존 응답만으로 검증할 수 없음. 앞선 2개 화면 실험에서 VLM은 요청받은 후보 범위를 그대로 근거 시간으로 반환해 이를 독립적인 위치 추정으로 인정할 수 없었음.

## 구현한 보수적 처리

통합 DINO 경로에서 각 화면의 224틱 구간이 다른 Stage1 후보나 강제 검토 구간과 겹치는지 기록함. 다른 후보가 보이면 VLM 답변을 버리지 않고, 그 답변을 원 후보의 확정 이상 또는 확정 정상 제거로 집계하지 않고 `uncertain`으로 남김. VLM의 이상 채널은 `provisional_channels`에, 기존 후보는 `retained_for_review_channels`에 보존함. 겹치는 후보를 자동 병합·삭제하거나 GT로 판단하지 않음.

요청에 맞춰 통합 경로의 보라색 경계선을 제거함. prompt는 이미지의 축이 tile-relative임을 밝히고 후보의 상대 범위가 어디인지 숫자로 알려줌. 주황색은 확대 범위라는 것도 명시함. 단 숫자를 전달하는 것만으로 VLM의 시간 읽기가 정확해지는 것은 아니며, VLM 답의 앵커링도 생길 수 있음. 다른 후보가 화면에 없더라도 Stage1이 생성하지 못한 변화가 섞일 수 있으므로 이 보호는 시간 귀속의 완전한 보장이 아님.

## 비용과 한계

기존 SMD 28대 계획을 GT 없이 범위만 계산한 결과 1,091개 core 중 433개(39.7%)에 다른 후보가 화면에 있었음. 사후 GT와 겹친 core 414개 중에서도 190개(45.9%)가 포함됨. 하나의 GT나 하나의 부모가 여러 core로 나뉠 수 있으므로 event recall이 아님. 화면 겹침은 실제 VLM 혼동의 증거가 아니며, 이 규칙은 좋은 이상 판단도 매우 많이 보류할 수 있음. `uncertain`을 정상이나 삭제로 취급하면 실제 recall 손실로 이어질 수 있음.

기존 저장 계획을 이용한 노출 빈도 집계이므로 새 VLM 성능 평가가 아님. 현 단계에서 production-ready, F1 향상, 시간 귀속 해결이라고 주장하지 않음. 특히 통계 기반 case 43은 DINO 통합 결과와 다름. 28대 계획에는 이 변경 적용 전 Stage1 JSON이 들어 있어 앞서 수정한 DINO zoom 중심을 재생성한 결과도 아님.

`pipeline_final/results/scope_guard_20261109/example.png`는 machine-1-1의 기존 DINO 후보를 같은 reference 방식으로 다시 그린 단일 화면이며, 보라색 경계 없이 검은 시계열과 주황 확대, reference가 렌더링되는 것을 확인했음. label을 사용하지 않은 화면 확인임. 실제 VLM 호출은 수행하지 않았음.

코드: `pipeline_final/contracts.py`, `stage2/run_stage2_review_hfz_v2.py`. 계약 테스트 21개와 관계 보조정보 테스트 6개 통과. 기존 결과 폴더는 바꾸지 않았고 코드가 바뀐 실행은 새 출력 폴더를 사용해야 함.

다음에는 사전에 고정한 독립 event 표본으로 1) 원래 방식, 2) 범위 보류 방식, 3) 실제 위치 확인 방법을 동일 후보에 비교하고 정상 경보 감소, 보류율, 이상 확정률, GT 시간 및 채널 보존을 함께 봐야 함. 자동 확정된 결과만으로 recall을 계산하지 않고 보류를 따로 보고해야 함.
