# Stage2 후보 삭제 조건 수정

## 확인한 오류

통합 DINO 경로의 VLM prompt는 `normal_repeat`이 **화면에 나온 채널과 해당 후보 가설에 대한 판정**이며 보지 않은 채널의 정상 여부를 뜻하지 않는다고 설명함. 그런데 집계기 `summarize_core`는 페이지의 채널들이 모두 normal이라고 답하고 참조가 지원되는 경우, 전체 채널을 보았는지 확인하지 않고 후보 구간을 `rejected_candidate`로 바꿈. Stage1이 실제 이상 채널을 화면에 넘기지 않은 경우, 그 미검토 채널의 이상과 함께 구간이 사라질 수 있음.

또한 동일 채널이 여러 페이지나 추가 검토에 등장했을 때 지원되는 참조가 한 번이라도 있으면 해당 채널을 supported로 처리했음. 다른 페이지에서 같은 채널의 참조가 불안정하거나 누락되어도 정상 제거를 막지 못하는 논리 오류임.

## 수정

1. 전체 채널을 검토하지 못했다면 모든 화면이 normal이어도 이벤트는 `uncertain`으로 남김. 이미 본 채널의 normal 의견은 원 응답에 보존함.
2. 같은 채널이 나온 모든 페이지에 해당 채널의 참조 품질 정보가 있고, 각각 지원되며 audit 경고가 없을 때만 그 채널을 supported로 처리함.
3. 보류된 후보에서 기존 채널과 추가 검토 요청 채널을 `retained_for_review_channels`에 명시함. 이 목록은 확인된 이상 채널이 아님.

변경은 `pipeline_final/contracts.py` 집계에 한정됨. 점수·후보·이미지·VLM 응답을 바꾸지 않음. 다만 파일 해시가 변했으므로 `run_pipeline`의 기존 실행 폴더는 원래의 재현성 검사에 따라 새 실행에 재사용할 수 없음. 기존 기록은 수정하지 않았음. 불확실 후보가 많아질 수 있으므로 precision 향상이나 recall 개선을 주장할 수 없음. 전체 채널을 보았다는 사실과 좋은 reference도 정상임을 보장하지 않음.

## 검증과 범위

가상 데이터에서 일부 채널만 검토한 정상 응답이 구간 전체 삭제로 이어지지 않는지, 같은 채널의 다른 페이지에 reference 경고가 있으면 삭제하지 않는지, 누락 응답·추가 검토도 보류되는지 검사함. 계약 테스트 19개, coupling 테스트 6개, 별도 범위 검사 테스트 3개 통과.

기존 48개 사례에서는 normal 제거 응답이 0개여서 이 수정의 실측 precision/recall 효과를 평가할 수 없음. 또한 그 사례는 통계 Stage1 기반의 GT 선택 화면이고, 이 변경은 기존 DINO 통합 집계기용임. 같은 후보 전체 페이지를 실제로 돌리는 별도 평가가 필요함.

남은 문제: 인접 event가 zoom에 같이 보일 때 시각적 증거를 올바른 후보에 귀속하는 능력은 아직 증명되지 않았으며, 보라색 경계 없는 실험과 기존 통합 prompt/render 계약은 다름. 이 수정이 해당 문제를 해결했다고 해석하면 안 됨.
