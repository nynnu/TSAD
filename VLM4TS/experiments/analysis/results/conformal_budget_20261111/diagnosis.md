# 보정된 경보 예산 (conformal) 검증 (2026-11-11)

분류: Exploration. 코드: `conformal_budget.py`(방법 + 자체 검증), `evaluate_conformal_smd.py`, `evaluate_conformal_dino.py`, `evaluate_conformal_tsb.py`.
방법: 14틱 블록마다 채널별 통계의 꼬리 확률을 train로 구하고(Fisher 합산), 보정용 train 블록에 대한 conformal p-value가 α 이하이면 경보. 필요한 상수는 목표 오경보율 α 하나. 장비 내에서 train를 fit 50% / 보정 25% / 감사 25%로 나눔(GT는 평가에만 사용).

## 1. 정상 구간 오경보율이 목표에 맞는가 (핵심 질문)

| 데이터 | 점수 | 정상 test 블록 오경보율 / α | 비고 |
|---|---|---|---|
| SMD 28개 장비 | 통계 점수, 고정 보정 | 2.3~5.6배 | train→test 정상 분포 이동 |
| SMD 28개 장비 | 통계 점수, 최근 블록 전부를 참조에 포함 | 1.1~1.3배 | |
| TSB-AD-U 226개 시계열, 11개 도메인 | 통계 점수, 고정 보정 | 전체 0.7~0.8배, 도메인별 대부분 0.5~1.2배 | Daphnet 21.7배, OPPORTUNITY 19.6배(α=0.01) |
| 같은 데이터 | 최근 블록 전부 참조 | Daphnet 1.7배, OPPORTUNITY 0.4배 | 이동이 큰 도메인도 맞음 |
| SMD 개발 장비 3개 | DINO spike+height | 고정 보정 1.3배 (α=0.01), 감사 구간 1.2배 | |

- 고정 보정의 오경보율 통제는 정상 분포가 변하지 않는 도메인에서는 맞고, 변하는 도메인(SMD, Daphnet, OPPORTUNITY)에서는 크게 어긋남.
- 참조에 최근 블록을 전부 넣는 방식은 이동이 있는 도메인에서도 목표의 0.4~1.7배로 유지됨.
- 설계 교훈: 참조에 "경보가 나지 않은 블록만" 넣는 변형은 오경보율이 오히려 늘어남(SMD 1.1배→2.3~5.6배 수준 그대로, TSB 일부 도메인 악화). 지속되는 정상 이동은 경보로 걸러져 참조에 들어가지 못하기 때문.

## 2. 후보 선별력 (점수에 달려 있음)

- 통계 점수(한 틱 최대 변화): SMD 28개 장비에서 사건 F1 0.2~0.3, TSB에서도 낮음. 현재 DINO Stage1(구간 정밀도 0.40, 사건 재현율 0.88)을 대체하지 못함.
- DINO 점수로 같은 구조(개발 장비 3개): α=0.03에서 경보 7.0%, 구간 정밀도 0.457, 사건 재현율 0.875, 사건 F1 0.600. 현재 Stage1 규칙은 같은 장비에서 경보 4.5%, 0.521, 0.917, 0.664. test 전체의 중앙값/MAD를 쓰는 현재 규칙보다 F1이 0.06 낮지만, test 통계를 전혀 쓰지 않고 오경보율을 목표로 통제함.
- 채널 합산 방식: 가장 작은 꼬리 확률만 쓰면(min) DINO에서는 train 후반 자체가 이미 fit 범위를 벗어나 α≤0.03에서 경보가 0개. 로그 꼬리 확률의 합(Fisher)으로 바꾸면 정상 작동.

## 한계

- DINO 결과는 개발 장비 3개뿐. 나머지 장비의 train DINO 점수는 CPU(약 1장/초)로는 계산할 수 없어 만들지 못했고, 2-x·3-x 장비로는 평가하지 못함.
- 다른 도메인 확인은 약한 통계 점수와 단변량 시계열만 사용. 다변량 다른 데이터셋은 이 컴퓨터에 없음.
- "정상 블록"은 GT에 이상 틱이 없는 블록이라 라벨 누락이 있으면 오경보율이 과대 계산됨.
- 이 구조는 오경보 "수"를 통제할 뿐, 어떤 후보가 라벨상 정상인지 구별하지는 않음(SMD의 정상 spike 문제는 여전히 남음).
