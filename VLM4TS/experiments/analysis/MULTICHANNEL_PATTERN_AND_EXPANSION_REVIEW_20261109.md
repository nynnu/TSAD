# 다채널 정상 패턴 점검과 추가 검토 조건 수정

## 사후 파형 검사

기존 GT 선택 사례 두 개에 대해 후보 전체의 31틱 파형을 보고 train 전체에서 세 채널이 **같은 시점에** 가장 비슷한 구간을 찾았음. 그림 `results/multichannel_train_patterns_20261109/joint_matches.png`에서 검정은 test, 파랑은 train이며, 위는 GT 비겹침 [840,854)의 ch9·11·12, 아래는 GT 겹침 [22291,22310)의 ch0·1·2임. 위의 세 채널이 train [20236,20267)에서 유사한 크기와 시점으로 동시에 변화함을 눈으로 확인했음.

이는 앞의 한 틱 높이만 비교한 것보다 구체적인 정상 이력 근거지만, train에도 문제가 있을 수 있고 GT 비겹침이 실제 정상을 증명하지 않음. 또한 이 사후 검색은 **후보의 전체 모양**과 사후 VLM 선택 채널을 이용했으며 train 전체에서 가장 잘 맞는 것을 찾았음. 따라서 예측 시 과거 문맥만으로 reference를 고르는 기존 방식과 공정한 비교가 아니고, 인과적 결론이나 자동 정상 판정이 아님. 도표의 전/후 15틱을 모두 보는 관찰 지연이 있음. 재현 `audit_multichannel_train_patterns.py`.

## 별도의 train 분리 점검

같은 7개 GT 선택 후보에 대해 VLM 결과 대신 Stage1 순서의 첫 세 채널과 Stage1 표시 peak 주위 31틱을 사용해 별도 다채널 패턴 거리를 실험함. 각 장비의 train 앞 50%만 은행·정규화, 다음 25% 중 32개 윈도우로 경험적 순위 보정, 마지막 25% 중 16개 윈도우로 nominal-normal 점검함. 전체 31틱을 사용하므로 offline/delayed 방식이며 GT는 모델에 주지 않음. 새 점수는 기존 Stage1·Stage2 판정에 연결하지 않았음.

두 GT 비겹침 1-2 후보의 경험적 상위꼬리 순위 p는 각각 0.333, GT 겹침 1-2 후보는 0.030이었음. 1-6의 GT 비겹침 두 후보는 각각 0.061, GT 겹침 두 후보는 각각 0.030이었음. 하지만 1-6의 GT 겹침 e00015에 쓰인 채널 조합은 마지막 정상 train의 16개 샘플 중 4개(25%)도 같은 p≤0.05 기준에 걸렸음. 표본은 매우 적고 시간 의존이 있으며 32개 보정으로 최소 p는 1/33임. Stage1이 선택한 peak·채널을 정상 쿼리에서 같은 방식으로 재선택해 보정하지도 않았으므로 전체 탐지기의 오류율을 보장하지 않음. GT로 사례를 고른 7개에 대한 post-hoc 결과이며, p는 이상 확률이 아님. 현재 이 수치로 threshold를 조정하거나 자동 제거하면 안 됨. 상세 `results/multichannel_shape_calibration_20261109/summary.json`.

## 발견한 추가 검토 누락

이전 `--expand-uncertain-channels` 옵션은 각 페이지의 raw VLM 응답이 uncertain일 때만 추가 채널을 보여줬음. 그러나 VLM이 anomalous로 답해도 이웃 후보가 같은 화면에 보여 **집계 결과가 uncertain**일 수 있고, 화면에서 본 일부 채널만 normal이라는 답도 미검토 채널 때문에 전체 후보가 uncertain일 수 있음. 기존 코드는 이 경우 확장하지 않았음.

옵션을 켠 경우 초기 페이지 전체와 reference 품질을 집계한 **core 상태가 uncertain일 때** 미검토 채널을 추가 검토하도록 고쳤음. 이웃 후보 보류를 사용하지 않는 `report` 정책과 사용하는 `hold` 정책은 각 정책의 결과에 따라 동작함. 입력 GT를 쓰지 않고 최대 한 차례 추가 round이며, 이 옵션은 여전히 기본 off임. VLM에 모든 채널을 추가로 보내면 호출·시간 비용이 커질 수 있음.

추가 테스트는 VLM raw 응답이 anomalous여도 hold의 이웃 후보 조건으로 core가 uncertain인 경우, hold에서만 미검토 채널을 검토하는지와 미완료 페이지에서는 확장을 시작하지 않는지를 확인함. 계약 테스트 26개 통과. 기능 수정이 precision/recall을 개선했다는 실제 데이터 근거는 아직 없고, 새로운 호출을 다시 하지 않았음. 다음으로 독립 장비의 정상 train에서 **같은 후보 생성·채널 선택·focus 선택 절차를 전체로 재현한 calibration**과, 동일 후보의 실제 추가 호출 비용 및 시간 범위 귀속을 평가해야 함.
