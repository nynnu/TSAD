# Stage1 후보와 Stage2 보존 비교

## 조건

machine-1-6의 통계 evidence-v2/routing-v3 후보에 대해 기존 Stage2 응답을 재분석함. GT를 참고해 고른 GT 겹침 24개, GT 비겹침 24개 화면이며 각각 하나의 페이지를 분석함. GT를 이용한 사례 선정과 사후 평가 외에 모델 입력에 GT는 쓰지 않았음. 원래 DINO 기반 최종 파이프라인의 전체 성능이 아님. 같은 event의 다른 페이지, 누락 채널 추가 검토와 전체 부모 집계는 분석 대상이 아님.

`uncertain`은 정상 또는 이상 확정이 아니라 후보와 화면의 채널을 보류 상태로 유지함. `anomalous`는 응답의 이상 채널만 잠정 유지함. `rejected_candidate`는 후보를 제외하되 원래 실험의 참조 품질 조건을 사용함. 이 평가는 가능한 보수적 운영 방식의 사후 시뮬레이션이며, 실제 최종 통합 시스템을 이 데이터 전체에 다시 실행한 결과가 아님.

## 후보 구간

| GT와의 관계 | 화면 수 | 이상으로 응답 | 정상으로 제거 | 보류 |
|---|---:|---:|---:|---:|
| 후보가 GT와 겹침 | 24 | 2 | 0 | 22 |
| 후보가 GT와 겹치지 않음 | 24 | 1 | 0 | 23 |

GT 비겹침 24개 중 13개는 더 넓은 224틱 화면에 다른 GT 시간이 들어옴. 비겹침 후보에 대한 VLM 판정이 화면 안의 다른 사건에 영향을 받았는지 이 데이터만으로 확정할 수 없음. 24개씩 의도적으로 뽑은 표이므로 이를 전체 precision/recall로 계산하면 안 됨.

## 채널

GT 겹침 24개 화면에 대해 각 사건의 GT 채널 집합과 해당 화면의 채널만 비교함. annotation은 event 단위 채널의 합집합이어서 해당 틱에서의 반응이나 원인 관계를 증명하지 않음. 같은 채널이 여러 사건에 나오면 여러 번 셈.

| 항목 | 결과 |
|---|---:|
| GT 채널 등장 횟수 | 249 |
| 화면에 이미 있던 GT 채널 | 110 |
| 해당 화면에 표시되지 않은 GT 채널 | 139 |
| 보류 후보를 포함해 Stage2 뒤 유지되는 GT 채널 | 101 |
| 화면에 있었으나 확정 이상 응답의 선택 목록에서 빠진 GT 채널 | 9 |
| 사건별 화면 채널 precision 평균 | 0.573 → 0.589 |
| 사건별 화면 채널 recall 평균 | 0.638 → 0.607 |

표시되지 않은 139회는 **Stage1이 전부 놓쳤다는 뜻이 아님**. 이 분석에는 페이지 하나만 들어가므로 다른 페이지에 있을 수 있음. 평균 precision은 보류 상태의 후보도 유지해 계산한 채널 구성 비율이며 확정 이상 precision이 아님. 개별 event에 대해 계산 후 평균하므로 110/249와 같은 마이크로 비율과 다름. 22개 보류를 그대로 남겼으므로 수치는 선택적인 일부 확정 판단의 영향이며 Stage2 전체 precision 향상을 입증하지 않음.

별도 세 장비 통계 후보 coverage 기록에서 GT event에 한 번이라도 겹친 비율은 8/8, 10/10, 29/30이었음. high+review 후보 합집합의 사후 관측이며 최종 Stage2 recall 또는 경계 정확도가 아님. 특히 한 개의 매우 긴 후보가 여러 GT event와 겹칠 수 있음.

## 판단

이 선택 사례에서 Stage2는 GT 비겹침 후보를 확정 제거하지 않았고 다수를 보류했음. 따라서 현재 자료는 Stage2가 오탐을 줄였다는 근거가 되지 않음. 채널 역시 일부 화면에서 GT 채널이 부족하거나, 이상으로 확정한 페이지에서 GT 채널 일부가 선택 목록에서 빠졌음. 원인이 Stage1 스크리닝인지 페이지 분할인지, 모델 판정인지, 경계 밖의 인접 event인지 분리하려면 전체 후보의 모든 페이지와 요청된 추가 페이지를 처리해야 함.

전체 SMD 통합 계획에는 28대 2,261페이지가 있으나 저장된 전체 실행은 Stage2 응답이 0개임. 기존 통합 28대의 Stage1→Stage2 precision/recall을 지금 계산할 수 없음. 다음 평가는 GT를 사용하지 않고 entity와 후보를 미리 정한 뒤 동일 후보·모든 페이지를 처리하고, 보류를 제거 또는 정상으로 치지 않는 세 가지 결과(이상·정상 제거·보류)를 따로 보고해야 함. 또한 표시된 zoom 내부에서 후보 밖 변화가 귀속되는지 살펴야 함.
