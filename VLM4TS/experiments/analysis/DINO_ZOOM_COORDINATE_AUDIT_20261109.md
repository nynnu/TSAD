# DINO 확대 중심 좌표 오류 점검

## 범위

기존 DINO Stage1 (`stage1_final/stage1.py`)의 검토임. 이전 case 43은 통계 evidence-v2/routing-v3 결과라서 이번 DINO 코드의 버그로 해당 사례가 발생했다고 주장할 수 없음.

## 확인된 오류와 수정

DINO 그림은 224틱이고 16개 열이므로 점수 한 열은 전체 시간축에 고정된 14틱에 대응함. 기존 코드는 후보 시작 `a`부터 14틱 단위를 다시 계산했음. 후보 `a`가 14의 배수가 아니면 가장 높은 점수가 나온 원래 열이 아닌 다른 열에 확대 중심이 놓일 수 있었음. 후보 범위 자체를 만드는 코드가 아닌 채널별 zoom 위치 코드의 오류임.

수정은 먼저 실제 최대 점수의 절대 시간으로 DINO 열을 찾고, 그 열의 중심을 해당 후보와 열의 교집합 안으로 제한함. 후보 구간, 후보 채널, 점수 및 threshold는 변경하지 않음. 기존에 저장된 Stage1 JSON과 렌더링은 자동 갱신되지 않으므로 수정 코드를 사용해 별도 출력으로 다시 생성해야 함. 수정된 코드로 JSON을 만들 때 기존 DINO 점수 cache를 활용할 수 있으나 원래 JSON을 새 결과로 오인하지 않도록 분리해야 함.

## 실제 고정 점수 재계산

동일한 저장 DINO 점수에서 이전·수정 좌표만 비교함. 서로 다른 실험 또는 다른 채널 후보 집합이 아님. 채널당 최대 점수 동률에서는 numpy argmax가 처음 위치를 고름. `old_wrong_column`은 기존 중심이 선택된 14틱 열 밖인 행 수임.

| SMD 장비 | DINO 후보 채널 행 | 확대 중심 변경 | 기존 중심이 다른 열 | 최대 이동 |
|---|---:|---:|---:|---:|
| machine-1-1 | 479 | 75 | 24 | 8틱 |
| machine-1-2 | 494 | 21 | 6 | 11틱 |
| machine-1-6 | 775 | 53 | 18 | 10틱 |

예시 그림 `results/dino_zoom_alignment_20261109/example_alignment.png`는 machine-1-2 ch9의 원래 파형, 점수 열, 수정 전후 확대 중심을 표시함. 색으로 표시된 후보와 점수 열은 사후 분석용이며 VLM 입력 이미지가 아님. DINO 열이 최대인 것이 실제 변화의 정답 위치라는 뜻은 아님.

GT와 겹치는 후보 가운데 DINO 채널이 하나 이상인 사건의 넓은 60틱 zoom과 GT 시간의 교집합 여부는 세 장비에서 각각 8/8, 8/8, 28/28로 수정 전후 같았음. GT 채널 정답은 고려하지 않은 사후 조건부 집계이므로 전체 recall이나 VLM F1이 아님. 따라서 이 버그 수정으로 성능이 개선됐다는 증거는 아직 없음.

## 추가로 확인한 구조적 한계

- 원래 DINO Stage1은 test 전체 score percentile과 test MAD를 이용함. train-only calibration도, 미래 시점을 보지 않는 온라인 평가도 아님. 정상 참조 분포 변화가 있으면 threshold가 달라질 수 있음.
- 탈주기는 `uniform_filter1d`의 기본 centered smoothing을 사용하므로 점수 시점에 미래 문맥이 포함될 수 있음. 현재 결과를 causal online detection으로 설명하면 안 됨.
- Stage1의 정답은 후보 구간이며 정확한 event boundary로 보장되지 않음. 타일이나 zoom이 원래 후보 밖의 이웃 후보를 포함할 수 있음. 현 통합 경로는 보라색 구간을 전제로 작성되어 있고, 보라색을 지운 별도 실험과 같지 않음. 범위 없는 VLM 답변을 특정 후보에 자동으로 귀속하면 안 됨.
- DINO 점수는 14틱 해상도이며 이미지 인코더의 receptive field가 열 내부로만 제한된다고 가정할 수 없음. 이 좌표 수정은 DINO가 실제 이상을 정확히 찾는다는 보장이 아님.
