# 10월 가설 로그 — DINOv2로 spike 잡기

**목표**: 탈주기가 놓친 spike(GT 길이 ≤15틱, 135개)를 DINOv2로 잡는다.
**평가**: point-wise F1 + event 단위(이상 1개 = 1개) 둘 다 본다.
**나중에 볼 것**: 225틱 초과 긴 이상 — 개수는 13개뿐이지만 탈주기가 놓친 틱의 57%.

## 지금까지 결론 (가정 1~4)
1. **DINOv2는 spike를 알아보는 능력이 있다** — 높은 spike vs 평범한 선/작은 튐 AUROC 0.975~0.996.
2. **정상 spike는 원래 자주 튀는 곳에 몰려 있다** — GT spike의 82%는 주변 300틱에 비슷한 높이의 정상 spike가 없음 (있는 건 7개 채널뿐).
3. **이상/정상 spike를 가르는 열쇠는 "갑작스러움"** — 갑작스러움 하나로 0.961, DINOv2 768개만으론 0.71~0.78.
→ 방향 후보: DINOv2로 spike를 찾고, 갑작스러움으로 이상인지 거른다.

## 출발점 (확인된 사실)
- 탈주기가 놓친 이상 212개 중 spike 135개(64%), 그러나 틱 기준으로는 7% → point-wise F1에는 거의 안 잡힘. 26주차 +0.018이 작았던 이유일 가능성.
- 세 방법(z-score / 탈주기 / DINOv2 patch-KNN) 모두 놓친 spike 중 36개는 "값은 train 범위 안 + 모양만 튐".

## 가정 1 — train patch와 최근접 거리로 비교하면 spike 위치가 낯설게 나온다
- 실험: 이상 5개로 patch 낯섦 그림 (`dino_inside.py`, `dino_inside.png`)
- 결과: 범위 안 spike는 주변과 낯섦이 비슷 → 안 튐
- 해석: train에 비슷한 spike가 있어 "본 적 있는 모양"으로 판단됨. train 기준 비교의 한계. 참고로 PCA상 DINOv2의 1순위 구분은 "선 vs 배경".

## 가정 2 — 탈주기가 못 잡는 이상은 spike다
- 실험: 기존 데이터로 확인 (탈주기 놓친 이상 길이 분포 + 26주차 1-1, 1-2)
- 결과: 놓친 212개 중 spike 135개(64%). spike recall 0.222 vs 긴 이상 0.499(2.3배). 희석은 1~3틱 52배 > 4~7틱 30배 > 8~15틱 29배.
- 해석: 맞음. 단 "spike만"은 아님(1/3은 spike 아님). → **탈주기는 짧은 이상일수록 못 잡는다 (60틱 평활화가 묻음).**
- 추가 확인: 이상 1개당 50% 이상 맞히면 "잡음" 기준, 세 방법 모두 spike를 가장 못 잡음 (z-score 28% / 탈주기 22% / DINOv2 21%, 225틱 초과는 42% / 64% / 69%). 26주차 최종 모델은 코드가 남아 있지 않아 비교 못 함.

## 가정 3 — DINOv2 patch 벡터(768) 안에 spike 정보가 들어 있다
- 실험: `exp_patch_groups.py`. 탈주기가 놓친 spike 96개 창(entity 11개)에서 선 patch를 A(GT spike) / B(정상 구간에서 바닥선 밖으로 튄 patch) / C(바닥선)로 나눔. 768개 전부로 분류기 → 처음 보는 entity에서 AUROC.
- 결과: A vs C 0.996, **A vs B 0.944**. 위치만으로는 A vs C 0.915, A vs B 0.779.
- 시행착오: ① spike를 항상 가운데에 그렸더니 위치만으로 AUROC 1.000 → 무작위 위치로 수정. ② 바닥선을 전체 픽셀 중앙값으로 잡았더니 높은 spike에 끌려 올라감 → 열별 중앙값으로 수정.
- 해석: DINOv2 벡터에는 위치 이상의 spike 정보가 있음. 단, B는 대부분 바닥선 바로 위의 작은 튐이라 "비슷하게 높은 정상 spike"와 구분되는지는 아직 모름.
- 추가 실험: B 중 "같은 창에서 GT spike 높이의 절반 이상 튄 정상 열"을 T(높은 정상 spike)로 분리 (T 있는 창 20개, T patch 252개).
  - 결과: A vs B(작은 튐) 0.975 / **A vs T 0.751** (위치만 0.536). 그림 `exp_patch_groups/T있는창_*.png`.
  - 해석: 높은 spike vs 작은 튐은 쉽게 가르지만, **GT spike vs 똑같이 높은 정상 spike는 중간 정도(0.75)**만 가름. 그림상 T 중엔 GT spike와 모양이 거의 같은 것(machine-1-6 ch17), GT 바로 옆에 붙은 것(라벨 경계 문제 의심), spike가 아닌 level 하락(machine-1-6 ch5)도 섞여 있음.
- 추가 확인 (라벨 탓인가?): 높은 정상 spike를 GT에서 50틱 이내(201 patch) / 50틱 밖(51 patch)으로 나눔.
  - 결과: A vs 50틱 이내 0.780 / **A vs 50틱 밖 0.708** (위치만 0.483 / 0.559).
  - 해석: GT 근처를 빼도 오르지 않음 → **라벨 탓이라는 가정은 지지 안 됨. DINOv2가 "GT spike vs 똑같이 높은 정상 spike"를 진짜로 중간 정도만 가름.** (50틱 밖은 51 patch뿐이라 흔들릴 수 있음) 덤으로, 높은 정상 spike의 80%가 GT 50틱 안에 몰려 있음 → 이상은 혼자 오지 않고 무리지어 오는 경향.

## 가정 4 — 이상 spike는 "조용한 곳에서 갑자기" 튀고, 정상 spike는 원래 시끄러운 곳에서 튄다
- 근거(눈으로): `compare_gt_vs_normal_spike/` GT spike 5개 vs 높은 정상 spike 5개 비교 그림
- 실험: `exp_suddenness.py`. 갑작스러움 = spike 높이 ÷ 주변 ±100틱 흔들림(robust std, 하한 = train 범위 1%). DINOv2 안 씀, 신호에서 직접 계산.
- 결과: GT spike 96개 중앙값 **66.7** vs 높은 정상 spike 59개(7개 채널) 중앙값 **4.0**. **AUROC 0.961**. 정상 spike 95% 지점(7.3)보다 큰 GT spike = **94%**.
- 해석: 맞음. 같은 높이라도 "주변이 조용한데 튀었나"가 이상/정상을 가름 (DINOv2 768개의 0.71~0.78보다 훨씬 잘 가름).
- 추가: GT spike의 82%는 주변 300틱에 비슷한 높이의 정상 spike가 아예 없음 → 치우침은 고칠 문제라기보다 데이터의 모습.
- 주의: 정상 spike가 7개 채널에서만 나와 표본이 치우침. 정상 12개는 이진 신호 채널이라 값이 0. 분석 대상은 탈주기가 놓친 spike 135개 중 채널 라벨이 있는 96개(71%).

## 가정 5 — DINOv2의 spike 능력을 극대화하려면, spike가 768개 숫자에 어떤 특징으로 들어가 있는지부터 안다
### 5-1. 소수 숫자에 몰려 있나, 골고루 퍼져 있나
- 실험: `exp_spike_direction.py`. A(GT spike) vs 일반 선(B+C), patch 3,766개.
- 결과: **숫자 하나(#635)만으로 AUROC 0.936**, #735 0.915. 0.8 넘는 숫자 38개. 분류기로 고른 상위 10개 → 0.934, 50개 → 0.976, 768개 전부 → 0.984. 가중치는 넓게 퍼짐(50% 차지에 205개).
- 해석: spike 정보는 **몇몇 숫자에 강하게 실려 있으면서, 비슷한 정보가 여러 숫자에 겹쳐서 퍼져 있음**. 50개 정도면 거의 다 담김.

### 5-2. "spike 방향"으로 256칸 전부(배경 포함) 칠하면 spike 자리만 밝아지나
- 실험: `exp_spike_heatmap.py`. (a) 635번 숫자 하나 (b) 768개 방향(그 entity 빼고 학습한 분류기). 그림 `exp_spike_heatmap/히트맵_*.png`.
- 결과: 창마다 점수 1등 patch가 GT spike인 비율 **635번 36% / 768방향 65%**. 배경 포함 256칸 AUROC **0.856 / 0.955**.
- 해석: 768방향은 spike 열이 뚜렷하게 밝고 배경은 어두움 → DINOv2로 만든 spike 탐지기로 쓸 만함. 635번은 선 patch끼리는 잘 갈랐지만(0.936) 배경을 넣으면 무너짐: 1등이 **늘 같은 배경 칸**에 몰림 ((7,11)에서 22/96번, (3,5)에서 12번) → 위치에 고정된 DINOv2 artifact로 보임 (attention 그림에서 보인 고정된 밝은 칸과 같은 현상 의심, register 없는 모델).

### 5-3. GT 라벨 없이 가짜 spike로 "spike 방향"을 배워도 진짜 GT spike를 찾나 (zero-shot 유지)
- 실험: `exp_synthetic_spike.py`. train(정상)의 41개 (entity, 채널)에 가짜 spike 6개씩 (길이 1~15틱, 위/아래 50:50, 주변 흔들림의 10~200배, 뾰족/네모/한점, 위치 무작위). 가짜 spike patch vs 나머지 선 + 배경 30칸.
- 1차 시도: 배경을 학습에 안 넣었더니 배경이 밝아짐 → 1등 32%, AUROC 0.897.
- 2차(배경 추가) 결과: 진짜 GT 그래프에서 **1등 patch가 GT spike 78%, 256칸 AUROC 0.982** → **GT로 학습한 방향(65%, 0.955)보다 좋음.** 선 patch: A vs C 0.961 / A vs B 0.885 / A vs 높은 정상 spike 0.800 (GT 방향 0.751보다 좋음).
- 해석: 라벨 없이도 spike 탐지기를 만들 수 있음 → zero-shot 유지 가능.
- 발견: 아래로 꺼지는 가짜 spike는 132개 중 49개만 그래프에 보임 — 채널 대부분이 바닥(train 최솟값) 근처라 아래로 꺼져도 그래프 바닥에 잘림. **지금 그리는 방식(train min/max 고정)은 아래 spike를 숨김.**
- 확인 필요: 예시 중 "아래" spike 하나(machine-1-6 ch9)가 위로 튄 모양으로 보임 — 주변 중앙값 계산 확인 필요.
- 고쳐야 하나? → 진짜 GT spike 96개 중 **아래로 꺼지는 건 2개뿐**이고 둘 다 그래프에서 보임 (위 94개 중 93개는 14픽셀 이상 움직임). **SMD에서는 지금 고칠 필요 없음.** 다른 데이터셋으로 갈 때 다시 볼 것.
- 아래 spike 고침 (가짜 spike 생성 쪽 문제):
  - 1차: 바닥까지 남은 공간 안에서만 꺼지게 → 아래 38개 모두 보이지만, 공간이 좁아 크기가 흔들림의 1~4배로 깎임(출렁이는 채널에 몰림). 결과 1등 78%, AUROC 0.983, 높은 정상 0.771.
  - 2차: 아래도 "흔들림의 10배 이상 꺼질 공간"이 있을 때만 → 아래 15개(위 123개). 결과 **1등 88%, 256칸 AUROC 0.989, A vs 높은 정상 spike 0.860** (A vs C 0.980, A vs B 0.941).
  - 해석: 애매한 가짜 spike(흔들림 속에 묻힌 꺼짐)를 빼니 전부 좋아짐 → **가짜 spike도 "조용한 곳에서 갑자기"여야 함**(가정 4와 일치). 아래 spike 수는 적지만 GT도 아래는 2/96뿐.

## 가정 6 — spike 방향은 긴 이상(16~224틱)에는 안 먹힌다
- 실험: `exp_long_anomaly_check.py`. 탈주기가 놓친 16~224틱 GT 이상 중 채널 라벨 있는 34개. GT 열 선 patch vs 정상 열 선 patch를 spike 방향 점수로.
- 결과: **AUROC 0.803** (예상보다 높음). 그림 `exp_long_anomaly_check/긴이상_히트맵.png`.
- 그림 관찰: "긴 이상" 중 상당수가 사실은 **spike 여러 개가 몰린 것**(machine-1-3 ch11, 1-4 ch11 등) → 잘 잡힘. **네모 모양 고원**(machine-3-5 ch18 151틱, 1-5 ch25)은 **올라가고 내려가는 세로 모서리만 밝고, 평평한 윗부분은 안 밝음.**
- 해석(잠정): spike 방향은 사실상 **"세로로 선 선분" 탐지기**. 긴 이상은 시작/끝 모서리는 잡지만 몸통(높은 상태로 유지되는 구간)은 못 잡음.

## 가정 7 — 긴 이상 모양(spike 묶음 / 산 / 모자)도 가짜로 배우면 몸통까지 잡힌다
- 근거: 탈주기가 놓친 긴 이상 그림(`missed_long/`)을 보고 나연이 분류 → ① spike 묶음 ② 산(완만히 올라갔다 내려옴) ③ 모자(급상승-지글지글 유지-급하강). (+ 흔들림만 커지는 것도 보임)
- 실험: `exp_synthetic_shapes.py`. 28 entity × 38채널 중 무작위 채널(라벨로 채널 안 고름 → 누수 해결)에 4종류 가짜 이상 각 250장.
- 시행착오: ① 크기가 커서 천장에 잘림 → 산이 모자처럼, 모자는 지글거림 사라짐 → 천장/바닥까지 남은 공간 안으로 제한. ② 이상 구간 열의 바닥선까지 '이상'으로 가르쳤더니 정상 바닥선 점수가 올라감 → 바닥선 행은 뺌.
- 결과(최종): 긴 이상 34개 AUROC **spike만 배운 방향 0.832 vs 4종류 0.800** / spike 96개 1등 88% vs 89%.
- 그림 `exp_synthetic_shapes/산모자_실제비교.png`: 4종류는 실제 모자/산의 윗부분이 조금 밝아지지만, **정상 구간의 지글거리는 선도 같이 밝아짐**(machine-1-3 ch19, 1-5 ch25).
- 해석: patch 하나만 보면 "모자 윗부분의 지글거림"과 "평소 지글거리는 선"이 똑같이 생김 → **몸통은 patch 혼자서는 구분 불가, 옆/평소와 비교(맥락)가 필요** (나연이 말한 "옆에꺼랑 얼마나 다른지"). 덤: 실제 산/모자는 대부분 train 최댓값을 넘어 그래프 천장에 잘려 있음.

## 전체 실행 — spike 탐지기(가짜 spike로 배운 방향) vs 탈주기, SMD 28 entity 전체
- 실행: `run_spike_detector.py` (38채널 × 비중첩 224틱, 약 12만 장) → `eval_spike_detector.py` (결과 `spike_scores/eval_result.txt`). 임계값은 26주차와 같은 오라클.
| 모델 | pooled F1 | macro F1 | P | R | spike≤15틱 | 16~224틱 | 225틱 초과 |
|---|---|---|---|---|---|---|---|
| 탈주기 | 0.451 | 0.527 | 0.357 | 0.613 | 38/173 (22%) | 54/118 (46%) | 23/36 (64%) |
| spike 탐지기 | 0.160 | 0.181 | 0.102 | 0.370 | **99/173 (57%)** | 52/118 (44%) | 10/36 (28%) |
| 갑작스러움만 (DINOv2 없음) | 0.203 | 0.250 | 0.146 | 0.329 | 64/173 (37%) | 33/118 (28%) | 7/36 (19%) |
| spike × 갑작 (섞기) | 0.204 | 0.232 | 0.150 | 0.316 | 86/173 (50%) | 35/118 (30%) | 4/36 (11%) |
| spike & 갑작 (거르기) | 0.176 | 0.200 | 0.149 | 0.214 | 76/173 (44%) | 34/118 (29%) | 3/36 (8%) |
| 탈주기 OR spike×갑작 (참고) | 0.457 | 0.540 | 0.358 | 0.633 | 66/173 (38%) | 59/118 (50%) | 23/36 (64%) |
- 해석: spike 탐지기는 **spike를 탈주기의 2.6배(22%→57%) 잡음**, 갑작스러움만(37%)보다도 많이 잡음 → DINOv2의 기여 확인. 하지만 단독 point-wise F1은 낮음(precision 0.10, 틱 기준이라 spike 비중 작음). 탈주기와 OR로 붙이면 F1 +0.006(0.451→0.457), spike 탐지율 22%→38% (탈주기가 놓친 spike 66개 추가).
- 오탐 분해: 오탐 틱의 97%가 GT에서 14틱 넘게 떨어진 정상 구간(칸이 넓어서 생긴 건 3%). 예측 덩어리 3,071개 중 GT와 겹치는 건 15%.

### 가정 5 결론
- "DINOv2 patch로 spike를 보게 하면 된다" → **patch로 spike를 볼 수 있는 능력은 확인**(가짜 spike로 배운 방향, spike 탐지율 22%→57%). 하지만 **그대로(raw) 쓰기엔 정상 구간 오탐이 너무 많음**(precision 0.10).
- 역할 분담: 큰 이상 = 탈주기(64% 잡음), spike = DINOv2. 긴 이상 몸통은 patch 혼자 보기 어려움(가정 7).

## 가정 8 — spike 오탐이 많은 이유를 분석하면 고칠 수 있다
- 원인 후보 1 — "완벽하게 곧은 선을 spike로 착각" (machine-3-10 ch6: 값 0.900~0.902, 그림상 칼같이 곧은 선인데 그 행 전체 점수 6.8. 노이즈 넣은 가짜 평평한 선은 -3.4). 그림 `spike_scores/평평한선_오탐_비교.png`. 짐작: 가짜 네모/한점 spike의 선이 칼같이 곧아서 "곧은 선 = spike"로 배움.
  - 하지만 오탐 2,582개 중 그림에서 선이 2픽셀도 안 움직인 경우는 **63개(2%)뿐** → 진짜 문제지만 **주 원인은 아님**.
  - (처음 짐작 "선이 위쪽에 있으면 spike"는 틀림: 노이즈 있는 평평한 선은 높이와 상관없이 점수 낮음)
- 원인 분석 2 — 임계값 문제인가? → **아님.** GT 맞힌 덩어리 점수 중앙값 8.9 vs 오탐 7.5, 점수로 가르는 AUROC **0.604**. 임계값을 올리면 맞힌 것도 비슷한 비율로 줄어듦. → 탐지기 입장에서 오탐도 진짜 spike만큼 spike처럼 생김.
- 원인 분석 3 — 특정 채널에 몰리나? → **몰림.** 쓸 수 있는 채널 872개 중 상위 52개(6%)가 오탐의 50%, 상위 162개가 80%. 오탐 1~5위가 전부 **5번 채널**(machine-1-1, 3-4, 2-1, 1-7, 2-2 ch5) → 원래 spike 모양이 자주 나오는 채널. 가정 4("정상 spike는 자주 튀는 곳에")가 채널 단위로 보이는 것.
- **가정 8 결론: 미정.** 원인(5번 채널처럼 원래 자주 튀는 채널에 오탐이 몰림, 점수만으로는 오탐/진짜 구분 불가)까지는 분석했지만, 다른 방법(Dinov2_deseson_col_z 구조 활용)이 더 나아 보여 고치는 실험은 하지 않기로 함.

## 가정 9 — Dinov2_deseson_col_z 모델이 진짜 의미가 있었나?
- 설계: 단순히 부품을 빼서 F1을 비교하지 않음 (데이터가 바뀌면 달라질 수 있음). **부품마다 "어떤 경우에 강하고 어떤 경우에 약한지, 왜 그런지"**를 사례 단위로 봄.
  - 볼 부품: ① 1차→2차 넘기기 ② DINOv2 14틱 열 단위 ③ 잔차 이미지 ④ patch-kNN ⑤ z-score 교차검증 ⑥ DINOv2 자체(가장 중요)
  - 부품마다: 살린 것 / 망친 것 → 그림으로 공통점 → 원리로 설명
  - 사례 특징: 이상 모양(목록 미리 안 정함, 후보에서 시작해 보면서 추가·합치기) / 길이·갑작스러움 / 채널 성격(주기적·시끄러움·평평함)
  - 이상 모양 후보: spike(위/아래), spike 묶음, 산, 모자, level shift, 흔들림 증가, 켜졌다 꺼졌다, 멈춤, 추세 변화, 주기 변화
  - 선행 작업: 이 모델 코드가 없음 → 먼저 재현해서 F1 0.469가 나오는지 확인
  - ① 1차→2차 넘기기: 최종 식이 `1차 OR (DINOv2 AND z)`라 "1차 정상 구간에서만 2차"든 전체든 최종 결과 동일 (임계값도 결합 F1 기준으로 골라 동일). 계산 절약 장치일 뿐 → **맨 마지막에 확인.** (2차 보완 자체의 의미는 ⑤⑥에서 봄)
  - 실제로 볼 순서: ②~⑥, 핵심은 ⑥
- **발견: 원래 F1 0.469는 채널 선택에 GT를 씀** (26주차 로그 4-5, 4-6). ① GT spike 중 탈주기가 놓친 것의 원인 채널만 후보 ② 채널마다 GT로 임계값(dt, zt) ③ F1 오르면 채택, 아니면 버림 → 2차는 872개 채널 중 60개(약 7%)에서만 돌았음. 탈주기·z-score 등은 임계값에만 GT 사용 → 0.469 vs 0.451 비교는 이 모델이 유리한 상태.
- 재현 방식 결정: **GT 없이 38채널 전부**에 2차를 돌림, 임계값만 entity당 (dt, zt) 한 쌍 오라클. 코드 `run_dsz_allch.py`(DINOv2 버전 + 숫자 버전 B 동시 계산), 평가 `eval_dsz_allch.py`.
- **결과 (28 entity, `dsz_scores/eval_result.txt`)**
| 모델 | pooled F1 | macro F1 | P | R | spike≤15틱 | 16~224틱 | 225틱 초과 | 탈주기 대비 개선/동일/악화 |
|---|---|---|---|---|---|---|---|---|
| 탈주기 | 0.451 | 0.527 | 0.357 | 0.613 | 38/173 (22%) | 54/118 (46%) | 23/36 (64%) | |
| 원래 보고 (GT로 채널 선택) | 0.469 | 0.559 | 0.361 | 0.667 | | | | 18/10/0 |
| **DINOv2 버전 (GT 없이 38채널)** | **0.466** | 0.559 | 0.359 | 0.665 | 52/173 (30%) | 66/118 (56%) | 24/36 (67%) | 24/4/0 |
| 숫자 버전 B (GT 없이 38채널) | 0.459 | 0.560 | 0.352 | 0.662 | 55/173 (32%) | 71/118 (60%) | 24/36 (67%) | 25/3/0 |
- 해석: ① GT로 채널을 고른 효과는 작음 (0.469 → 0.466) → **모델의 효과(탈주기 대비 +0.015)는 GT 없이도 유지됨.** ② **숫자 버전도 거의 같음** (F1 −0.007, macro는 오히려 +0.001, spike·긴 이상은 숫자 버전이 조금 더 잡음) → DINOv2만의 기여는 평균 숫자로는 거의 안 보임 → ⑥에서 사례 단위로 봐야 함. ③ "악화 0"은 오라클 임계값 구조상 당연(아무것도 안 더하는 게 최선이면 탈주기 그대로).
